# Load test, 2026-10-23

The runs behind the README's capacity line. Public reads only, against Croft 0.6.7 (0.6.8 changes
nothing on the read path).

## Setup

| | |
|---|---|
| Version | Croft 0.6.7: public reads from the read cache and the database's read replicas (as in [the 2026-10-16 run](2026-10-16-load-test.md)), plus the output cache of Croft 0.6.6 |
| Hardware | four Raspberry Pi 4 (the site's own cluster): three run one Web, one API and one database instance each, the fourth (3.7 GB) runs neither |
| Path | the site's real ingress: a load balancer in front of the cluster, then Traefik, TLS 1.3 with ChaCha20-Poly1305 (the Pi 4 has no AES instructions) |
| Tool | k6 on a separate machine, open model (a fixed arrival rate), stepped ramp: the scripts in [`loadtest/`](../../loadtest/README.md) |

## Result

| Run | Clean up to | Breaks at |
|---|---|---|
| Page requests, no compression | **600 req/s**, p95 ~120 ms | ~780 req/s (p95 0.7 s); p95 over 2 s at ~800 |
| Page requests, `Accept-Encoding: br, gzip` | **800 req/s**, p95 80 to 185 ms | ~1,000 req/s (p95 0.7 to 1 s) |
| Visits (a page and all its assets, about 0.33 MB per visit) | **30 visits/s** (~10 MB/s), p95 120 to 200 ms | 35 visits/s (p95 2.2 s); fails from ~39 |

"Clean" means 0 errors and a p95 under 200 ms. At the break the three database nodes are at or
near 100 % CPU, and most of it is TLS in Traefik (0.6 to 1.1 cores per Traefik pod), then the Web
pods (0.45 to 0.6 cores each); the API and the database stay under 0.1 core. So on this hardware
the limit is encrypting the responses, not Croft or PostgreSQL.

## Compared with 2026-10-16

The README's earlier "about 160 requests a second" (Croft 0.6.0) had no output cache: each page
was rendered for every request. With the output cache, a rendered page is served from memory
until it changes, which moved the limit from Croft to TLS.

## What this does not show

- Anonymous reads only: no signed-in traffic, editor or uploads.
- This file is a summary of the owner's runs. The raw k6 output is not in this repository.
- Your cluster's limit depends on its CPUs: nodes with AES instructions encrypt far faster than a
  Raspberry Pi 4. Measure your own.
