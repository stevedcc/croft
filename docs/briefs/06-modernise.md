# Brief 06: bring the codebase up to .NET 10 house style

Read AGENTS.md first and follow it, including "Finishing a task". Load the `writing-dotnet10-code`
skill before writing any code; its defaults are the target for this whole brief. Implement the design
below; if it doesn't fit, stop and explain. One commit per item. The items are mostly independent: use
`subagent-driven-development`.

There are no production users and no data worth keeping. The dev database may be dropped.

**Already done before this brief** (by the orchestrator, don't redo): analyzers and code style are
enforced in `Directory.Build.props` and `.editorconfig`, and `dotnet format` has applied the
mechanical fixes (primary constructors, collection expressions, etc.). Keep the build warning-free.

**First, before any item:** run all three suites, including E2E on a restarted stack. The
orchestrator's format pass (`d3f5dc6`) passed the unit and API suites, but E2E hasn't been run on
it. If anything fails, stop and report; don't fix it inside an item.

**Behaviour must not change** except where an item says so. Existing tests must keep passing with
their assertions unchanged. Changing test *setup* to inject a `TimeProvider` is expected and fine;
say so in the commit message.

## Items

### 1. Entity keys are UUIDv7, generated by EF
- First write an API test that saves each entity type with a `Guid` key (Post, Category, Tag,
  MediaAsset, Feedback, PageView) *without* setting `Id`, then asserts the saved `Id.Version == 7`.
  Watch it fail or pass, and record which in the commit message: Npgsql's EF provider is expected to
  generate v7 for `Guid` keys by default, and this test proves it either way.
  - If it passes: remove every `Id = Guid.NewGuid()` from entity creation in `src/`.
  - If it fails: configure v7 generation once (a value generator, or `HasValueGenerator` in each
    entity's configuration), then remove the assignments. Don't scatter `Guid.CreateVersion7()`
    through services.
- Where code needs the id before `SaveChanges`, use `Guid.CreateVersion7()`.
- `LocalFileStorage` file names are not keys; leave `Guid.NewGuid()` there.

### 2. Time comes from `TimeProvider` only
- Replace every `DateTime.UtcNow` / `DateTimeOffset.UtcNow` in `src/` with an injected `TimeProvider`
  (already registered in both `Program.cs` files). In EF queries, read the time once into a local
  first (`var now = time.GetUtcNow().UtcDateTime;`) so it's sent as a parameter.
- `ScheduledPublisherHostedService`: pass the `TimeProvider` to its timer
  (`new PeriodicTimer(period, time)`), or to `Task.Delay(…, time, ct)`.
- Tests construct services with the existing `FakeTimeProvider` fixture where they control time.
- Add one test that proves a service now uses the provider: e.g. advance the fake clock past a
  post's `PublishedAt`, and the post becomes visible in the public listing. Break-it-once: put
  `DateTime.UtcNow` back and show the test fails.

### 3. Blazor "not found" is a real 404: already done in R3.5, skip
- R3.5 moved post, category and tag pages to `NavigationManager.NotFound()` and added a catch-all
  route for unknown URLs, with E2E tests on status and content. Nothing to do; don't change it.

### 4. `MapStaticAssets`
- In `Blog.Web/Program.cs`, replace `app.UseStaticFiles()` with `app.MapStaticAssets()`. In
  `App.razor`, reference the app's stylesheets and scripts with `@Assets["…"]`, so their URLs are
  fingerprinted.
- E2E: the home page's own stylesheet and the MudBlazor stylesheet are served with 200 (assert on
  the network responses, not on `<link>` tags being present), and the app's stylesheet URL is
  fingerprinted. Existing E2E tests still pass.
- If MudBlazor's or Blazor's assets don't resolve through `MapStaticAssets`, stop and report (rule 8).

### 5. API exception handling through `IExceptionHandler`
- Replace the inline `app.UseExceptionHandler(errorApp => …)` lambda in `Blog.Api/Program.cs` with an
  `IExceptionHandler` class in `Blog.Api/Errors/`, registered with `AddExceptionHandler<T>()`. Keep
  the response identical: same status codes, same ProblemDetails shape, no exception detail outside
  Development.
- If no test pins that response yet, add one before the change (an endpoint that throws returns
  500 ProblemDetails without a stack trace), then make the change. In .NET 10, handled exceptions
  are no longer logged by default; log them yourself, with `[LoggerMessage]`.

### 6. No blanket `catch (Exception)`
- At a background-loop boundary (`ScheduledPublisherHostedService`, `PostSummaryBackfillService`),
  catching everything keeps the service alive. Keep it, but make it
  `catch (Exception ex) when (ex is not OperationCanceledException)`.
- Elsewhere (`PostService` media deletion, `MediaService`), catch only the exceptions the operation
  can actually throw (e.g. `IOException`, `UnauthorizedAccessException`) and let the rest propagate.
- Each change keeps or adds a test for the handled case.

### 7. Comments explain why, not history
- Remove brief, task and ruling references from comments in `src/` ("(brief 04)", "Task R2.2",
  "ruling R2-R5", …). Keep the explanation, drop the reference. If a comment is only a reference,
  delete it. Find them with `grep -rnE "brief|Task R[0-9]|ruling" src`.

### 8. One fresh `InitialCreate` migration (do this after every other item, including 9 and 10)
- Before deleting anything, produce the full schema from the current migrations:
  `dotnet tool run dotnet-ef migrations script -p src/Blog.Api -s src/Blog.Api -o /tmp/schema-before.sql`.
- Delete everything in `src/Blog.Api/Migrations/`, then
  `dotnet tool run dotnet-ef migrations add InitialCreate -p src/Blog.Api -s src/Blog.Api`, and
  script it to `/tmp/schema-after.sql`.
- Compare the two scripts. The only allowed differences are migration ids and history inserts, and
  statement order. Put the diff, or a summary of it, in the commit message. Any table, column,
  index, constraint or default that differs means: stop and report.
- Drop the dev database (`dotnet tool run dotnet-ef database drop --force -p src/Blog.Api -s src/Blog.Api`),
  then run `./start-local.sh`, which applies the new migration. All three suites pass on the fresh
  database.

### 9. Primary constructors use their parameters
- `dotnet format` converted classes to primary constructors but kept the fields
  (`private readonly BlogDbContext _db = db;`). Remove those pass-through fields and use the
  parameter directly (`db.Tags…`), as the skill shows. Keep a field only where it does more than
  copy the parameter. Mechanical; the existing tests are the safety net.

### 10. Analyzer warnings to zero, then warnings are errors
- Fix the remaining analyzer warnings (`dotnet build Blog.slnx` lists them), including:
  - `LocalUrl.IsLocal`: use `StringComparison.Ordinal` (CA1310). It's the open-redirect check, so
    keep or add a test for `//evil.example` and `/\evil.example`.
  - The `Log…` calls flagged by CA1848/CA1873: convert to `[LoggerMessage]` partial methods.
- Then add `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>` to `Directory.Build.props`, and
  show a clean build. Suppress a rule only with a one-line reason in `.editorconfig`, and say so
  in the report.
